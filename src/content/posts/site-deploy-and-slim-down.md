# 把个人站点搬上云的一天：部署、瘦身与迁移实录

今天把「个人主页导航站」和「博客」两件事一起推进了，从本地代码一路折腾到云端上线，整个过程值得记录一笔。

## 一、主页导航站：部署到 Cloudflare Pages

之前一直放在本地跑的主页导航站（纯静态 HTML/CSS/JS，黑客风代码雨背景那个），今天终于正式部署上线了。

因为我的博客占用了 GitHub Pages 的根路径（`ayato233.github.io`），GitHub Pages 用户级站点一个账号只能有一个，所以主页选择了 **Cloudflare Pages**——连接 GitHub 仓库后，push 代码就会自动构建部署，全程零成本。

部署前还顺手做了一件事：**把 git 历史清成了单条提交**。之前开发过程攒了 8 个零碎提交，里面混着不少过程性的信息，用 orphan 分支重建后只剩一条干净的初始提交，强迫症表示很舒适。`.gitignore` 里不该出现的注释也一并清理了，规则挪到了本地的 `.git/info/exclude`，仓库保持纯粹。

## 二、博客瘦身：-35MB 的快乐

博客一直挂在 GitHub Pages 上，国内访问慢。排查后发现除了服务器在海外，**站点本身也太重**：

- 4 个本地 mp3 共 21MB —— 但播放器走的其实是 meting 远程歌单，这些文件**根本没在用**
- Live2D 看板娘（Pio）模型 6.4MB —— 决定整个移除
- 两个字体 ttf 共 14MB —— 转成 woff2 后省了 7.7MB

动手过程：
1. 删掉没用的 mp3，顺手把本地播放列表常量清空
2. 看板娘从组件、配置、类型定义到 public 资源全部清理，全局搜索确认无残留
3. 字体用 fontTools 转 woff2：`loli.ttf` 10.3MB → 4.6MB，`ZenMaruGothic` 3.6MB → 1.5MB

瘦身完本地构建验证通过，仓库从 65MB 降到约 30MB，线上不再需要下载 21MB 的音乐和 6.4MB 的模型，首屏加载明显变快。

**一个有意思的发现**：音乐播放器本来就是点击才加载的（设置 audio.src 才拉取），所以"点击才加载"这件事系统已经做对了，真正的优化是直接删掉没用的资源。

## 三、博客迁移：GitHub Pages → Netlify

GitHub Pages 的服务器在美国，绕地球一圈的延迟怎么优化资源都救不回来，于是决定迁移到 Netlify——恰好旧博客 `smile32.netlify.app` 之前就在 Netlify 上，账号还在，直接把构建配置指向现在的博客仓库，几分钟就完成了替换。

实测对比：Netlify、Vercel、Cloudflare Pages 三个平台在我网络下延迟其实非常接近（900ms~1.3s），差别不大。所以选平台不必纠结速度，看哪个顺手、有现成资源就用哪个。

## 小记

今天最大的感受：**「不用」就是最好的优化**。删掉没在用的 21MB 音乐、移走不要的看板娘，比任何压缩技巧都来得直接有效。以及，云平台的自动部署（push 即上线）确实省心，改完代码提交，剩下的交给流水线。

愿以后的折腾都像今天一样，干净利落。
